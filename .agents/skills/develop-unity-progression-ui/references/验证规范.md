# 验证规范

## 静态检查

- `*.AutoGen.cs` 和 `UIConfig.Auto.cs` 没有手写业务修改。
- 手写 UI 代码没有直接引用数据库 Parser、Root 或磁盘保存接口。
- 所有写操作通过 Module 公开命令完成。
- 所有成功刷新都有明确事件或同步返回依据。
- Panel 类名、UIConfig 名、Prefab 名和路径一致。
- `m_...` 字段名称、类型和 AutoGen 一致。
- 列表选择使用业务 ID，不依赖不稳定下标。
- 关键字段、方法、事件参数和状态逻辑有 UTF-8 中文注释。

## 编译检查

- 执行目标项目真实 C# 编译命令。
- 检查生成代码是否进入正确程序集或项目文件。
- 搜索旧字段、旧事件和旧 Panel 名残留。
- 生成文件有变化时确认来源是 Unity 生成器，不是手改。

## Unity 行为检查

- Panel 能正常打开、关闭、返回和重复打开。
- 打开参数为空、合法和非法时行为明确。
- 首次打开能完整显示当前玩家数据。
- Module 事件发生后，已打开界面能正确刷新。
- 列表为空、只有一项和多项时布局与选择正常。
- 解锁、升级、装备、领奖或消耗成功后显示一致。
- 资源不足、满级、已领取和非法操作不产生错误写入。
- 快速连续点击只提交一次。
- Item 回收重用后没有旧图标、旧文本、旧红点或旧回调。
- 分辨率、横竖屏、安全区和文本长度由用户完成视觉验收。

## 协作验收

代码侧交付：

- 字段契约与实际 AutoGen 对照结果。
- Panel/Item 手写逻辑。
- Module API 和 EventConst 使用清单。
- 编译和行为验证结果。

用户侧验收：

- Prefab 节点、锚点、布局和字段命名。
- 切图、字体、材质、动画和特效。
- 不同分辨率和真机视觉效果。
- Unity Inspector 引用和最终 AutoGen 生成。

未执行 Unity 运行验证时，必须说明原因和剩余风险，不能只以编译成功代替界面验收。
