# 角色、装备与属性流程

## 基础职责

角色与装备模块负责：

- 解锁和拥有状态。
- 当前等级、最大等级和升级消耗。
- 装备槽位、装卸和上阵选择。
- 永久属性合成。
- 可升级、可装备和红点状态推导。
- 进入战斗前生成稳定的属性快照。

配置描述基础数据和成长规则，玩家存档只保存拥有、等级、槽位和选择等真值。

## 解锁与升级

标准流程：

1. 校验配置、拥有状态和功能开放。
2. 校验当前等级小于最大等级。
3. 读取“从当前等级升到下一等级”的配置，明确等级 key 语义。
4. 完整校验消耗。
5. 原子扣除消耗并修改等级。
6. 保存后发送升级完成和属性变化事件。

最大等级可来自对象配置、独立升级表或全局规则，但同一对象只能有一个权威来源。找不到升级配置时不能默认免费升级。

## 装备槽位与上阵

- 装备前校验拥有、槽位、角色限制、互斥关系和状态合法性。
- 同一槽位重复装备同一对象应作为幂等成功或无操作，不执行卸下再重装。
- 换装是一次事务：旧装备解除与新装备写入同时成功或同时失败。
- 上阵数据只保存必要选择，不把完整配置或合成属性重复写进存档。
- 删除、回收或失效装备时修复所有引用它的槽位和上阵数据。

## 属性定义边界

- 系统养成和战斗都会使用的稳定属性定义在 `cfg/attribute/`。
- 只在战斗流程中使用的时长、状态阈值、镜头、AI 或命中参数定义在 `cfg/battle/`，不创建重复的战斗属性表。
- 当养成效果与某个战斗数值挂钩时，先确认它是否需要跨系统持久化和合成；需要则定义共享 attribute，不需要则留在战斗专属配置。
- 每个属性必须注明数值类型、单位、缩放规则、加减顺序、上下限和舍入方式。

## 属性合成

属性合成至少区分：

1. 配置基础值。
2. 等级或品质带来的永久成长。
3. 永久解锁、天赋或装备加成。
4. 进入战斗前的最终基础值。
5. 战斗中的 Buff、技能和临时变化。

前四类由养成系统计算，战斗只消费结果并叠加第五类。合成顺序和 Ratio 单位必须来自配置规则，禁止 UI 和战斗各写一套公式。

## 战斗快照

进入战斗前生成只读或深拷贝快照，至少包含身份 ID、等级、选中装备及其最终基础属性。快照应满足：

- 同一场战斗期间不受局外升级影响。
- 字典、列表和嵌套对象不与存档共享可变引用。
- 战斗临时加成、耐久变化和状态不能回写养成基础数据。
- 战斗需要新增共享属性时，先更新属性配置和快照生成，再调整战斗读取者。
- 快照缺失或配置异常时明确失败或使用有依据的兼容兜底，不能静默生成零属性角色。

## 红点

红点由当前配置、玩家资源、拥有状态、等级和槽位状态实时推导。资源变化、升级、解锁和换装成功后发送失效事件，红点系统重新计算；不要把“有红点”作为独立字段保存。
