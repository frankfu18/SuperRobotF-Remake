# 交互刷新与状态规范

## 刷新策略

- `OnShow` 做完整刷新，保证关闭重开后结果正确。
- 业务成功事件优先做定向刷新；依赖关系复杂时重新查询并完整刷新。
- 资源余额变化后，刷新货币栏以及所有依赖该资源的按钮状态。
- 列表数据变化后尽量保留当前业务 ID；该 ID 不存在时选择明确的默认项。
- 不通过 `Update` 轮询养成数据变化。

## 按钮状态

每个业务按钮至少区分：

- 可操作：正常样式，可点击。
- 条件不足：不可点击或点击后交给统一错误提示，遵循项目既有交互。
- 提交中：临时禁用，防止重复命令。
- 已完成/已领取：显示完成态，不再次提交。
- 满级：显示满级态，不再展示升级消耗。

UI 可以调用 `Can<Action>` 决定显示，但最终合法性仍由 `Send_<Action>` 再校验。

## 列表与 Item

- Panel 负责排序、筛选、选择和数据源。
- Item 只显示一项，并通过回调上报业务 ID。
- 不把 `Index` 作为长期业务身份；列表变化后下标不稳定。
- ViewData 包含显示所需的 ID、文本、图标、数量、状态和回调，不暴露数据库写入口。
- Item 回收时清理临时动画、计时器和回调引用。

## 选择与详情

- 选择状态由 Panel 保存业务 ID。
- 列表刷新后先校验选中 ID，再刷新 Item 选中态和右侧详情。
- 点击当前已选项默认不重复执行昂贵操作；需要展开详情时明确区分“选中”和“执行”。
- 装备、角色或槽位互斥规则由 Module 判断，UI 只展示结果。

## 消耗、奖励和升级

- 消耗数量和图标来自配置或 Module ViewData，不在 UI 写死。
- 资源不足不做部分扣除；UI 只响应 Module 失败结果。
- 奖励领取成功后再打开奖励展示界面。
- 升级成功后刷新等级、属性差值、消耗、按钮、列表 Item 和红点。
- 满级时不得继续读取不存在的下一等级配置。

## 红点

- 红点由 Module 的 `Is...HasRedDot` 或 `Can...` 查询推导。
- 不单独在 UI 保存“红点已消失”真值。
- 相关成功事件后刷新当前界面红点和入口红点。
- 多级红点由下级状态向上聚合，UI 不反向修改子模块数据。

## 弹窗与导航

- 确认弹窗只负责收集确认结果，业务命令仍由发起方或明确回调执行。
- 打开新 Panel 时传强类型数据，避免依赖全局临时变量。
- 单例 Panel 已打开时要遵守 `UISystem` 的实例规则，不重复打开制造双重回调。
- 页面关闭后需要刷新来源页面时，优先依赖成功事件；只有纯展示选择才使用关闭回调。

## 错误与异常

- `Send_XXX` 返回 `false` 时恢复按钮状态并保持原数据。
- 配置缺失、资源加载失败或打开参数错误时使用项目日志系统输出包含 Panel、业务 ID 和操作名的错误。
- 可选 Prefab 字段使用项目提供的安全读取方式；必需字段缺失应尽早暴露，不能静默跳过核心功能。
- 异步回调执行前确认 Panel 尚未关闭、目标 Item 尚未回收、请求仍是最新版本。
