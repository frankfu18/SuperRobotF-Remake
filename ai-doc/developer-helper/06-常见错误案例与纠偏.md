# 06. 常见错误案例与纠偏

## 1. 这一节的目的
- 这不是单纯的问题列表。
- 这里整理的是当前项目里已经真实出现过、并且后续项目很可能再次出现的错误模式。
- 目标是让开发人员遇到类似情况时，先快速定位“属于哪一类问题”，再用正确方式修正。

## 2. 错误分类总览
- 需求理解偏差
- UI 结构与代码理解不一致
- 初始化刷新与轻刷新混用
- Prefab 字段未真正 Apply
- 把业务逻辑写进错误层级
- 规则没沉淀，后续反复改
- 过早做表现，导致返工

## 3. 需求理解类错误

### 案例 1：把文档里的流程理解成了“交互优化版”
现象：
- 开发自己补了“点击另一个有色块节点可切换选中”
- 但需求文档并没有确认这条

问题本质：
- 没严格按需求文档章节执行
- 把“合理猜测”当成“正式规则”

纠偏方式：
- 回到需求文档对应章节逐条对照
- 优先按文档，不按个人直觉
- 文档没确认的地方，不要默认加交互优化

经验：
- 需求文档一旦够用了，就必须以文档为准

### 案例 2：把“需求讨论结果”留在聊天里，没有同步文档
现象：
- 后面回看时规则口径不一致
- 开发、策划、AI 各自记得不一样

纠偏方式：
- 每轮关键确认后立即同步到文档
- 涉及 UI 的同时更新 SVG

经验：
- 聊天记录不是正式规格

## 4. UI 结构理解类错误

### 案例 3：Panel 层级理解错，导致代码绑定逻辑错
现象：
- 以为某个节点在 `Container` 下
- 实际它在 `Content` 下
- 或者以为某个节点互为父子，结果其实平级

纠偏方式：
- 以真实 Prefab 树为准
- 用户一旦提供树结构截图，立即同步文档和示意图
- 不继续沿用旧理解写代码

经验：
- 真实 Prefab 结构优先于文字猜测

### 案例 4：把“显示对象”当成一定已经存在
现象：
- 代码依赖了并不存在的节点
- 或依赖了字段还没绑定的组件

纠偏方式：
- 新显示对象必须先列清单，让开发手动创建
- 依赖前先确认 Prefab 和字段已存在

经验：
- 先有对象，再写依赖对象的代码

## 5. 刷新时序类错误

### 案例 5：普通点击触发整块 Content 重建
现象：
- 只是点击一个节点选中
- 结果棋盘节点、目标组、连线、布局全重建
- 导致位置跳动、连线错位

问题本质：
- 没把“初始化级刷新”和“局内轻刷新”分开

纠偏方式：
- 切关 / 初始化：重刷新
- 选中 / 取消选中 / 普通移动：轻刷新
- 静态连线只在初始化后绘制

经验：
- 普通交互不要走关卡初始化流程

### 案例 6：布局依赖坐标的逻辑跑得太早
现象：
- 连线位置不对
- 节点到目标组的锚点错位

问题本质：
- 在 Layout 还没完成时就取位置

纠偏方式：
- 先强制刷新布局
- 再异步到下一帧做坐标换算和绘制

经验：
- 依赖真实 UI 坐标的逻辑必须晚于布局

## 6. Prefab 与绑定类错误

### 案例 7：Inspector 里看着绑定了，Prefab 资产里其实没写进去
现象：
- 运行时报空引用
- 但开发觉得“我明明已经挂上了”

问题本质：
- 改的是实例，不是 Prefab 资产
- 没有 Apply

纠偏方式：
- 出现这类问题时，检查实际 prefab 文件或重新打开 prefab 模式确认
- 明确提醒“要 Apply 到 prefab 资产”

经验：
- Unity 里“看起来挂了”不等于“资产里已经生效”

### 案例 8：AutoGen 已生成，但逻辑类未补齐
现象：
- 字段绑定类已经有了
- 但 Panel 逻辑类还没创建或没接事件

纠偏方式：
- AutoGen 生成后，补对应非 AutoGen 逻辑文件
- 明确职责：AutoGen 只绑定，逻辑写在 Panel 脚本

## 7. 架构边界类错误

### 案例 9：Module 直接碰 UI 坐标或对象
现象：
- 模块里直接写死 UI 坐标
- 或试图从模块里拿 Transform / Canvas 信息

问题本质：
- 违反“模块与显示层解耦”

纠偏方式：
- 模块只传索引或数据
- 坐标换算放到 Panel / View 层

经验：
- 模块只管规则和状态，不管真实显示对象

### 案例 10：把有职责的对象做成普通 Item
现象：
- 后面越来越多状态、模式、局部刷新逻辑塞进 Item
- 导致结构别扭、复用困难

纠偏方式：
- 判断这个元素是“列表单元”还是“功能视图对象”
- 有独立职责时，优先做自定义组件

经验：
- `Item` 不是万能容器

## 8. 规则沉淀类错误

### 案例 11：已经反复验证有效的规则，没写进 prompt
现象：
- 后面同类需求还在重复确认
- AI 和开发要反复对齐同样的规则

纠偏方式：
- 只要发现某条规则和当前业务本身无关、但跨项目适用
- 就提“项目全局规则”
- 确认后写进 `prompt.txt`

经验：
- 好规则要沉淀，不然就会反复消耗沟通成本

## 9. 推荐的排查顺序
1. 先看是不是需求理解偏了
2. 再看 Prefab 结构和绑定是否一致
3. 再看事件链路是否走通
4. 再看刷新层级是不是用错了
5. 最后再看算法和业务状态

## 10. 一句话总结
- 这次项目里的很多错误，不是代码能力问题，而是“规则、层级、刷新边界、文档同步”没有先对齐。
- 先把这些对齐，后面的开发效率会高很多。
