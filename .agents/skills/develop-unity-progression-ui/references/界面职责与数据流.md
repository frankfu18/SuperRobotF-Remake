## 1. 分层职责

### Prefab 与 AutoGen

- Prefab 保存视觉层级、组件、锚点、布局、默认显隐和序列化引用。
- `AutoGen` 只保存从 Prefab 生成的字段绑定，不包含业务判断。
- Prefab 和 AutoGen 是界面结构契约，不是玩家数据来源。

### Panel

- 接收打开参数，组织界面级状态、页签、选择、导航和刷新。
- 注册按钮与业务事件，调用 Module 查询或命令。
- 负责把业务数据转换成 Item ViewData，不直接修改数据库。

### Item

- 显示单个列表元素、卡片、奖励或槽位。
- 接收完整显示数据和回调，不自行查找父 Panel。
- 复杂 Item 可以调用只读 Module 查询补充显示，但修改操作应通过明确回调或公开命令完成。

### Module

- 拥有业务真值、校验、事务、数据库写入、错误码和成功事件。
- 提供 `Get...`、`Is...`、`Can...` 查询和 `Send_...` 命令。
- UI 不应知道 Module 内部 Parser、Root 数据和缓存结构。

### 配置

- 提供名称、图标、文本、等级上限、消耗、奖励和静态规则。
- UI 可以读取纯显示配置；涉及能否升级、能否领取等业务结论时优先调用 Module。
- UI 不复制配置到本地静态字典作为第二份真值。

## 2. 标准数据流

### 打开和首次刷新

```text
入口 -> UISystem.Open -> Panel.OnShow
     -> Module.Get/Is/Can 查询
     -> 构建 ViewData
     -> 刷新 Panel 和 Item
```

### 用户操作

```text
按钮点击 -> UI 做输入完整性和重复点击保护
         -> Module.Send_XXX
         -> Module 完整校验与原子修改
         -> 数据保存成功
         -> EventConst 成功事件
         -> Panel 事件回调重新查询并刷新
```

`Send_XXX` 返回 `false` 时，UI 不更新为成功状态。错误文本和弹窗优先复用项目的 `ErrorHandler` 或统一提示系统。

## 3. 生命周期职责

### `OnInit`

- 只初始化不依赖 Prefab 实例的轻量状态。
- 不访问尚未绑定的 `m_...` 字段。

### `OnBind` 与 AutoGen

- 由生成文件完成字段读取和 Item/List 初始化。
- 手写文件不重复绑定同一字段。

### `OnCreate`

- 初始化只依赖 Prefab、且仅需执行一次的对象。
- 建立 Item 回调、页签映射或本地显示缓存。
- 不把可能变化的玩家数据只刷新一次后永久缓存。

### `OnRegisterListener`

- 使用框架的 `AddButtonClick`、`SetButtonClick`、`AddEventListener` 等封装。
- 同一个按钮只保留明确的一条命令入口。
- 避免直接向全局事件中心注册而绕过容器自动解绑。

### `OnShow`

- 解析打开参数并执行完整刷新。
- 重置选择、提交锁、临时提示和上次打开残留。
- 需要保留上次选择时，必须明确该状态的所有者和失效条件。

### `OnUpdate`

- 默认不用轮询 Module 数据。
- 只处理倒计时、连续动画、拖动或必须逐帧同步的表现。
- 普通养成数据变化必须走事件刷新。

### `OnClose` 与 `OnDestroy`

- 清理临时回调、外部资源、计时器和提交状态。
- 不在关闭时偷偷提交未确认的养成修改。
- 框架自动回收的监听和 Item 不要重复销毁。

## 4. Module 接口约定

- 数据查询：`Get<Thing>()`、`Get<Thing>List()`、`Get<Thing>Info(id)`。
- 状态判断：`Is<Condition>()`、`Can<Action>()`。
- 写入命令：`Send_<Action>(...)`，返回 `bool` 表示是否成功提交。
- UI 需要失败原因但现有错误系统无法表达时，先在养成 Module 中补错误码或结果类型，不能在 UI 重写校验。
- 跨 Module 组合显示可以在 Panel 层读取多个只读接口；跨 Module 事务必须由业务编排层或 Module 完成。

## 5. 事件约定

- 事件名遵循目标项目规范，例如 `<Domain>_<ActionSuccess>` 或 `<Domain>_<DataRefresh>`。
- 只有数据成功提交后发送成功事件。
- 事件参数应足以做定向刷新，例如角色 ID、装备 ID、变化数量或槽位。
- 参数不足以稳定刷新时，事件只作为“已变化”通知，UI 重新查询 Module。
- Panel 使用框架监听封装，关闭和销毁时由框架统一解绑。

## 6. 禁止事项

- UI 直接访问 `<Domain>DataParser.Ins` 或修改数据库 Root。
- Item 内部绕过 Panel 发起跨模块复杂事务。
- 点击后先改界面数据，再假设 Module 一定成功。
- 把资源不足、满级、解锁条件等业务规则复制到 UI。
- 每帧查询整个角色、装备或物品列表来刷新界面。
- 手改 `*.AutoGen.cs` 或 `UIConfig.Auto.cs`。
- 为一个新界面另建第二套窗口管理、事件总线或对象池。
