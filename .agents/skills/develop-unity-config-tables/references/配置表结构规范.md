# 配置表结构规范

## 先确认项目事实

- 所有源配置从目标项目 `cfg/` 开始查找。
- 定位总入口 XML、模块 XML、对应 xlsx、生成脚本和生成输出目录。
- 目标仓库存在本地配置规范时，以本地规范为准。本文件只提供没有更具体约定时的默认规则。
- 编辑已有模块前，先搜索同模块和相邻模块的真实写法，确认生成器支持的语法。

## 模块与定义顺序

每个业务模块默认使用 `cfg/<模块>/<模块>.xml`，根节点命名空间与目录对应。新增模块后，把模块 XML 加入项目总入口；常见总入口为 `cfg/cfg_sc.xml`。

模块 XML 中按下列顺序组织定义：

1. `enum`
2. `bean`
3. `config`

不要把 `enum` 或 `bean` 插到 `config` 后面。字段中文说明写在 `<var .../>` 后，解释业务意义、单位或取值规则。

## 命名规则

- 枚举名使用大驼峰并以 `E` 开头，例如 `EEquipmentSlot`。
- bean 和 config 名使用大驼峰，例如 `EquipmentInfo`、`Equipment`。
- 字段名和 xlsx 文件名使用小驼峰，例如 `baseAttrDic`、`equipment.xlsx`。
- `ref="..."` 中的配置引用名使用目标项目要求的形式；默认使用全小写。
- 重命名前搜索旧类型名、旧访问方法、旧文件名和生成产物，形成完整迁移清单。

## 类型与引用

- 基础字段使用生成器支持的 `int`、`long`、`float`、`bool`、`string` 等类型。
- 同模块枚举或 bean 可直接写类型名；跨模块类型使用项目生成器约定的完整名称。
- 外键字段使用 `ref` 指向目标 config。确认引用名称与生成器注册名一致，不用 C# 类型名猜测。
- 集合按真实生成器语法定义，例如 `list,<类型>`、`map,<键类型>,<值类型>` 或项目已有的 `array:<类型>`。
- 父子 bean、多态 bean 和嵌套集合必须先在 XML 中建立明确结构，再设计 xlsx 展开列。

## 全局单行表

全局唯一配置默认使用 `mode="one"`：

- 不增加无意义的 `id`。
- 不增加无业务用途的备注列。
- 运行时按项目生成的单例配置访问方式读取。

## 变更约束

- 新增字段必须说明数据来源、默认值、单位、范围和运行时读取者。
- 删除或重命名字段前，先搜索源代码、其他配置和策划表中的所有引用。
- 不为了表面整洁调整无关字段顺序；字段顺序变化可能导致 xlsx 展开列整体错位。
- 不直接编辑生成代码修复结构问题。回到 XML 或 xlsx 源文件修正后重新生成。
