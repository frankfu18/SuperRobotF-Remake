# 验证规范

## 静态检查

- UI、引导和战斗没有直接修改持久化对象。
- 每类真值只有一个权威写入口。
- 事件在事务提交后发送，监听成对注销。
- 没有手改生成代码、硬编码配置映射或共享可变快照引用。
- 关键字段、公开方法、事务顺序、单位、迁移和兜底有清晰中文注释。
- 新文档和代码无乱码、占位符和无关项目数据。

## 配置验证

涉及配置时执行 `$develop-unity-config-tables` 的生成和验证流程：检查 XML/xlsx、引用、默认值、单位、生成类型、访问接口和旧生成文件清理。配置生成失败时先修源配置，不手改生成产物。

## 编译与自动测试

执行目标项目真实的配置生成、C# 编译和已有测试命令。新增纯计算逻辑优先覆盖单元测试；数据库和 Module 事务至少覆盖成功、失败和重复调用。

## 核心场景

1. 新用户初始化执行两次，不重复发资源。
2. 多货币、多物品消耗任一不足时，所有余额保持不变。
3. 奖励重复领取、按钮连点和重入回调不会重复发放。
4. 角色和装备完成解锁、升级、满级、槽位、换装与重复选择流程。
5. 保存后重启恢复全部真值；运行时缓存可重建。
6. 旧档缺字段或版本落后时安全迁移，重复迁移不破坏数据。
7. 红点由当前状态推导，资源变化后能刷新且无需保存红点。
8. UI 只通过查询、命令结果和事件刷新。
9. 战斗快照稳定、深拷贝，战斗临时变化不回写养成。

## 异常场景

验证未知配置 ID、负数数量、数值溢出、配置缺行、保存失败、迁移失败、背包容量不足、最大等级、装备引用失效和模块未初始化。每个异常应返回可处理结果并记录符合项目规范的日志，不能留下部分数据。

## 交付记录

列出修改文件、配置源、存档模型、公开接口、事件、迁移版本、生成与编译命令、自动测试和手动验证结果。没有执行的验证必须说明原因和残余风险。
