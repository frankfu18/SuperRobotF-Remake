# 系统功能流程

具体项目的配置结构、模块名称、错误码和 UI 体系可能不同。以下流程只定义通用职责和顺序，实现时必须映射到目标项目真实代码。

## 新用户初始化

读取初始化版本和默认配置，完整校验初始角色、装备、物品、货币与上阵选择，构造一次原子写入，成功保存后记录初始化版本。重复执行返回已初始化，不能再次发放。

## 增加或消耗货币与物品

调用 Currency 或 Item 公共命令，校验 ID、数量、上限和余额，提交并保存后发送旧值/新值事件。上层业务必须携带来源原因，UI 不能直接修改数量。

## 发放奖励

Bonus 先把配置解析为确定结果，业务层校验领取资格与幂等状态，再原子发放全部奖励并写领取状态。展示层读取实际发放结果。

## 角色解锁与升级

解锁校验未拥有、条件和消耗；升级校验拥有、最大等级和下一级配置。成功后更新角色真值，使属性缓存失效，保存并发送角色及属性变化事件。

## 装备解锁、升级与换装

解锁和升级复用经济事务。换装校验槽位与互斥关系，在同一事务中更新旧槽位和新装备。重复选择当前装备不重建数据。成功后使角色最终属性和战斗快照缓存失效。

## 上阵数据与战斗快照

战斗入口向养成模块请求快照。养成模块验证角色、装备和属性完整性后生成深拷贝；战斗模块只消费。局外升级发生在战斗中时，仅影响下一次新建快照。

## UI 与红点

面板打开时通过查询接口刷新；按钮点击提交命令；成功或失败通过回调、结果对象和事件反馈。红点监听资源、角色、装备和配置刷新事件后重新推导，UI 不保存红点真值。

## function 和 guide

功能入口系统负责开放状态、入口跳转和功能锁提示；引导系统负责步骤、遮罩和进度。二者只能调用养成模块公开查询与命令，并监听成功事件，不能直接改存档或复制事务规则。

## 商店、任务与活动扩展

- **商店**：保存限购和刷新状态，购买委托 Cost 与 Bonus。
- **任务**：保存必要进度和领取状态，奖励委托 Bonus。
- **签到/活动/通行证**：各自维护周期、进度和领取状态，经济变更仍走公共事务。
- **邮件**：附件先固定为奖励结果，领取必须幂等。

这些系统应建立独立业务模块，不把周期、任务目标或商品规则塞入 Currency、Item、Cost 或 Bonus。
