# 配置生成与代码接入

## 发现生成链路

修改前定位目标项目真实生成流程，至少确认：

- 总入口 XML。
- 配置生成脚本或命令。
- XML 和 xlsx 输入目录。
- 生成 C# 目录。
- 生成二进制或运行时数据目录。
- 运行时配置管理器和访问方法。

当前仓库常见命令是相对项目根目录执行：

```powershell
cmd /c "cd /d client && gen_config.bat < nul"
```

复制 Skill 到其他项目后，必须重新发现该项目命令，不能照搬当前仓库路径。

## 生成规则

1. 保存 XML 和 xlsx 源文件。
2. 执行项目生成器并检查退出码和错误输出。
3. 检查生成 C# 类型、字段、构造读取顺序和配置访问方法。
4. 检查运行时二进制配置是否更新。
5. 编译实际使用这些生成类型的程序集。

生成失败时回到源定义修复。禁止在生成 C# 中手工补字段，也禁止绕过生成器直接修改二进制配置。

## 运行时代码接入

- 通过项目配置管理器提供的强类型接口读取配置，不直接解析生成的二进制文件。
- 业务代码读取配置前处理“配置不存在”的异常路径，并遵循项目日志规范。
- ID、资源引用、枚举和 bean 类型继续由配置承载；不要在业务代码中复制一份硬编码映射。
- 配置负责基础数据，技能、增益或战斗临时变化放在运行时状态中，避免回写配置对象。

## 重命名与迁移

重命名 config、bean、enum、字段或 xlsx 时同步检查：

- 模块 XML 和总入口 include。
- 工作簿文件名、表头和展开列。
- 生成 C# 类型及访问方法。
- 项目文件、程序集引用和业务代码。
- 旧生成文件、旧运行时数据和旧配置访问残留。
- 文档、注释和其他配置中的旧名称。

生成器不会自动清理旧文件时，只删除已确认由本次重命名淘汰的生成产物，不扩大清理范围。

## 与业务方案对齐

涉及战斗、角色、装备、AI、资源或用户界面时，在实现方案中写清：

- 配置源表和字段。
- 数据单位、默认值与策划来源。
- 生成后的类型和访问入口。
- 初始化时机与运行时读取者。
- 缺失配置的兜底行为。
- 配置生成、编译和行为验证方式。
