# 养成界面从 0 到 1 开发流程

## 阶段 1：阅读需求与项目规则

读取效果图、策划文档、`AGENTS.md`、`ai-doc`、`docs/api/ui`、现有相似 Panel/Item、目标 Module 和事件定义。

完成标准：能明确界面入口、目标用户操作、业务结果、数据所有者和当前 UI 框架生成流程。

## 阶段 2：拆分界面状态

列出至少以下状态：

- 初始与默认选择。
- 已拥有、未拥有、锁定、可解锁。
- 可升级、材料不足、满级。
- 正常列表、空列表、筛选无结果。
- 正常提交、提交中、提交失败和重复点击。
- 奖励可领、已领、不可领。
- 红点显示与消失。

完成标准：每个按钮在每种状态下的可见性、可点击性、文本和点击结果明确。

## 阶段 3：确认养成 Module 契约

同时使用 `$develop-unity-progression-systems`：

- 找到真实 `Get...`、`Is...`、`Can...` 和 `Send_...`。
- 确认成功事件、事件参数和失败错误码。
- 缺接口时先在 Module 补公开接口，UI 不直接访问 Parser。
- 跨 Module 操作先确认事务所有者，不在 Panel 里串联多个可失败写入。

完成标准：所有显示和按钮操作都能映射到明确的查询、命令和成功事件。

## 阶段 4：确认配置来源

涉及新配置、图标、文本、消耗、奖励或等级数据时，同时使用 `$develop-unity-config-tables`：

- 写明源 XML/xlsx、字段、单位和生成访问接口。
- UI 只读取显示需要的配置。
- `CanUpgrade`、`CanUnlock` 等业务结论由 Module 提供。

完成标准：没有写死业务 ID、文本、消耗或等级上限。

## 阶段 5：输出 UI 逻辑方案和字段契约

复制 `assets/养成UI逻辑方案模板.md` 到项目方案目录并填写：

- Panel/Item 类和 Prefab 路径。
- 字段契约表。
- 打开参数和 ViewData。
- Module 查询、命令和事件。
- 界面状态矩阵。
- 用户需要完成的 Prefab 工作。

完成标准：用户可以只看契约完成 Prefab，不需要猜代码字段。

## 阶段 6：等待 Prefab 和 AutoGen

用户完成 Prefab 后执行：

- `GameObject/[UI] 生成脚本`。
- 新 Panel 通过 `PeekabooGame/UI/UI配置` 保存并生成配置。

代码侧读取实际 `*.AutoGen.cs` 和 `UIConfig.Auto.cs`。字段缺失、类型错误或命名不一致时，先反馈具体节点，不在手写代码绕过。

完成标准：生成文件可编译，Panel/Item 字段与契约一致。

## 阶段 7：创建手写 Panel 与 Item

文件默认放在 `Assets/HotUpdate/UI/Panel/<Domain>/`：

- `<Domain>Panel` 负责界面级状态、导航、事件和列表组织。
- `<Domain>Item` 负责单个元素显示和点击回调。
- 复杂打开参数使用 `st<PanelName>Data` 或项目现有强类型命名，不长期依赖无语义的 `object`/`CommonParams`。
- Item 显示数据使用 `st<ItemName>Data` 或只读 ViewData，避免直接传 Parser 数据。

关键字段、方法和流程补 UTF-8 中文注释。

完成标准：AutoGen 不含手写修改，逻辑类职责清楚。

## 阶段 8：接入生命周期与监听

- `OnCreate`：建立一次性的 Item 回调和本地映射。
- `OnRegisterListener`：绑定按钮和 EventConst。
- `OnShow`：解析参数并完整刷新。
- `OnUpdate`：只保留必须逐帧运行的表现。
- `OnClose/OnDestroy`：清理外部资源和临时状态。

按钮方法使用 `OnClick<Action>`，事件方法使用 `On<Domain><Action>`，刷新方法使用 `Refresh<Section>` 或 `RefreshAll`。

完成标准：多次打开关闭不会重复监听或残留旧选择。

## 阶段 9：实现显示刷新

推荐顺序：

1. 查询玩家真值和静态配置。
2. 构建当前界面 ViewData。
3. 刷新主信息、资源栏、列表、选中项和详情。
4. 最后刷新按钮状态、提示和红点。

列表使用稳定业务 ID 作为选择依据，不用列表下标长期代表角色或装备。

完成标准：事件刷新、重新打开和数据变化后都能得到相同界面结果。

## 阶段 10：实现操作命令

- 点击前只做输入格式、当前选择和重复点击保护。
- 调用对应 `Module.Send_XXX`。
- 返回 `false` 时解除提交锁，不伪造成功显示。
- 返回 `true` 后等待或响应成功事件刷新；同步命令也不能在 UI 复制数据库修改。
- 需要确认的高价值操作先打开公共确认弹窗。

完成标准：快速连点、资源不足、满级和非法选择都不会产生重复写入或错误 UI。

## 阶段 11：导航与公共界面

- 使用 `UISystem.Instance.Open/Close`。
- 奖励展示、确认弹窗、错误提示和货币栏优先复用公共 Panel/Item。
- 关闭当前界面再打开下一界面时，明确回调顺序和数据刷新责任。
- 引导或功能入口只调用本界面公开入口，不直接修改内部选择字段。

完成标准：返回、关闭、重复打开和叠层顺序符合 UI 栈规则。

## 阶段 12：静态验证和编译

- 搜索 UI 手写代码是否直接引用 `DataParser`、数据库 Root 或 Module 私有字段。
- 搜索是否修改 `AutoGen`。
- 检查所有 `m_...` 字段都来自当前 AutoGen。
- 检查事件名和参数顺序。
- 执行目标项目 C# 编译。

完成标准：无编译错误、无生成文件手改、无越层数据访问。

## 阶段 13：Unity 行为验证

逐项验证：打开、关闭、返回、首次进入、空态、列表滚动、切换、解锁、升级、资源不足、满级、领奖、重复点击、事件刷新、重新打开、分辨率适配和 Prefab 默认状态。

完成标准：代码行为正确，并将纯视觉或 Prefab 问题明确交回用户处理。

## 阶段 14：交付

列出：

- 已实现的 Panel/Item 行为。
- Module 查询、命令和事件。
- 生成文件和手写文件。
- 编译与 Unity 验证结果。
- 用户仍需完成的 Prefab、切图、布局、动画和视觉验收。
