# Unity 配置表开发

围绕目标项目 `cfg/` 下的源配置完成设计、表格编辑、代码生成和运行时接入。优先服从目标仓库的本地规则；没有更具体规则时，再使用本技能提供的默认约定。

## 强制工作流程

1. 先判断任务属于新增、扩展、迁移、重命名、数据调整还是故障修复。
2. 修改前阅读目标仓库的 `AGENTS.md`、`ai-doc`、`docs`、策划文档和配置表规范。优先查找 `config-table-rules.md` 或同类文档。
3. 检查 `cfg/` 的真实结构，定位模块 XML、对应 xlsx、总入口 XML、生成脚本、生成目录、运行时访问接口和使用方。
4. 新建项目基础配置、公共模块或经济框架时，读取 `references/项目框架通用配置.md`，先划分通用层与玩法层，再设计依赖顺序。
5. 已有配置必须先读取同模块 XML 和实际工作簿，不得只凭通用规则推测列布局。新增结构优先参考目标项目内同类型的 enum、bean、config、list、map 或全局表。
6. 先确定 XML 数据结构和运行时读取关系，再修改 xlsx 数据。结构不明确时停止实现并向用户确认，不能自行发明字段语义或数值。
7. 修改 XML 时读取 `references/配置表结构规范.md`；修改 xlsx 时读取 `references/Excel数据规范.md`。
8. 配置修改完成后读取 `references/配置生成与代码接入.md`，执行目标项目真实生成流程。禁止手动修改生成的 C#、二进制配置或中间产物。
9. 交付前读取并逐项执行 `references/配置验证清单.md`。

## 工作边界

- 配置源文件统一放在目标项目 `cfg/` 下；生成产物放到项目生成器规定的目录。
- Skill 不携带自写 XML、xlsx 或 C# 配置模板。需要新增内容时，从目标项目真实配置中提炼结构和填写方式。
- 通用配置文档只提供职责、依赖和扩展规则，不复制当前项目的业务类型、业务 ID 或策划数值。
- 不用文本拼接代替结构化表格编辑。处理 xlsx 时使用可解析并可渲染检查的表格工具。
- 不删除、重排或重写与当前需求无关的列、数据、格式和生成文件。
- 配置默认值必须来自策划文档、用户要求或已有约定。无法确认时记录待确认项，不擅自填业务数值。
- 关键字段、特殊单位、引用关系、兼容兜底和迁移原因使用清晰的 UTF-8 中文注释。

## 参考文档选择

- 项目基础配置、公共模块、经济框架和依赖分层：读取 `references/项目框架通用配置.md`。
- XML 模块、命名、类型、引用和定义顺序：读取 `references/配置表结构规范.md`。
- xlsx 表头、展开列、嵌套结构和视觉检查：读取 `references/Excel数据规范.md`。
- 生成脚本、生成类型、运行时读取和重命名清理：读取 `references/配置生成与代码接入.md`。
- 静态检查、生成、编译、乱码和数据验证：读取 `references/配置验证清单.md`。

## 与系统养成 Skill 配合

当需求涉及玩家存档、货币、物品、奖励、消耗、条件、属性、角色、装备、升级或上阵数据时，与 `$develop-unity-progression-systems` 一起使用：

1. 本 Skill 负责 `cfg/` 下的 XML、xlsx、字段类型、引用、默认数据、配置生成和生成结果验证。
2. 系统养成 Skill 负责玩家真值、持久化模型、Module、经济事务、事件、UI 查询接口和战斗快照生成。
3. 养成框架 Markdown 必须写清配置源路径、字段含义、单位、默认值来源、运行时读取者、生成命令和旧档迁移影响。
4. 配置表不能保存玩家当前等级、余额、拥有状态或领取状态；这些运行时真值由养成数据负责。
5. 共享属性定义放在 `cfg/attribute/`；只属于战斗流程的参数放在 `cfg/battle/`，不创建语义重复的属性表。

纯配置数据修正且不影响玩家存档、事务或运行时规则时，不展开系统养成 Skill 的实现流程。

## 与战斗 Skill 配合

当战斗需求明确涉及配置表、配置字段、枚举、属性、资源 ID、角色、装备或 AI 参数时，与 `$develop-unity-ecs-battle` 一起使用：

1. 战斗 Skill 负责规则职责、实体组件系统边界、运行时读取者和行为验证。
2. 本 Skill 负责 `cfg/` 源定义、xlsx 数据、配置生成、访问接口和配置验证。
3. ECS 框架 Markdown 的“配置与数据”部分必须写清来源表、字段含义、运行时读取位置、默认值来源、生成命令和迁移要求。

纯战斗代码修改没有配置影响时，不展开本 Skill 的表格修改和生成流程。

## 交付说明

说明修改的源配置、生成产物、运行时接入位置、执行过的生成和编译命令、数据验证结果，以及仍需策划或 Unity 编辑器确认的内容。若生成器或编译未能执行，必须明确说明原因。
