# 07. 开发人员提问模板与反馈模板

## 1. 这一章怎么用
- 这一章不是讲原理，而是给开发人员直接复制使用的模板。
- 当你不想每次临时组织语言时，可以直接从这里挑一段改一下再发给 AI。
- 这些模板都按照当前项目的协作方式整理，适合日常开发中高频使用。

## 2. 新需求，直接进入需求整理模式
适合：
- 只有主玩法描述
- 只有示意图
- 需求还比较模糊

模板：
```txt
你现在先不要写代码，先进入“需求整理与需求落地”模式。

我先给你一版初始玩法输入，请你帮我逐步整理成开发可直接使用的需求文档。

输入如下：
1. 游戏主玩法界面示意图：
   - 包含 UI 和游戏界面布局
   - 可以是 1-3 张不同状态的图
2. 游戏主玩法描述：
   - 用一段话描述核心玩法

可选补充：
3. PDF / Word 文档（如果有）：
4. 参考产品（如果有）：
5. 其他零散规则（如果有）：

要求：
1. 先整理核心玩法骨架。
2. 每轮只问最关键的一批待确认问题。
3. 需求文档持续更新。
4. 需要界面表达的内容同步输出 SVG 草图。
5. 当前阶段先不进入代码开发。
6. 生成的文件都放入 requirements 目录中
```

## 4. 需求已经明确，进入正式开发
适合：
- 需求文档已经够用了
- 准备开始开发方案协作

模板：
```txt
现在需求协作已经基本完成，下面进入开发协作阶段。

你的工作要求：
1. 先判断需求归属层。
2. 先参考 demo-game-setup.md 的组织方式，帮我产出一版开发方案。
3. 开发方案保存到 ai-doc/develop-setup 目录，并使用 md + svg 的格式呈现。
4. 先和我多轮沟通确认开发方案，确认没问题后再开始改代码。
5. 如果需要新增显示对象，先暂停并列出需要我手动创建的对象清单。
6. 如果发现已有同名脚本，先暂停并告诉我，优先复用已有脚本。
7. 代码实现时遵守当前项目脚手架、事件驱动、日志和注释规则。
```

## 5. 让 AI 继续往下做
适合：
- 前一个步骤已经确认
- 不想重复解释上下文

模板：
```txt
继续。
请基于我们刚刚已经确认的方案继续往下做，不要回退到旧方案。
如果需要我手动创建对象、确认规则或者处理 TODO-AI，再暂停告诉我。
```

## 6. 提编译错误
适合：
- Unity 编译报错
- C# 编译不过

模板：
```txt
出现编译错误，请按最新报错处理：

报错内容：
（粘贴完整错误）

要求：
1. 先定位根因。
2. 直接修复。
3. 如果修复会影响别的规则或流程，顺手说明一下。
```

## 7. 提运行时错误
适合：
- 空引用
- 逻辑错乱
- 状态切换异常

模板：
```txt
出现运行时问题，请按最新现象排查：

现象：
1. 我做了什么操作：
2. 实际结果：
3. 期望结果：
4. 报错堆栈（如果有）：

要求：
1. 先分析根因。
2. 告诉我你理解的正确流程。
3. 确认后再修改代码，或直接按已确认规则修复。
```

## 8. 提 UI 现象问题
适合：
- 布局不对
- 连线错位
- 颜色不对
- 选中态不对

模板：
```txt
当前 UI 表现不对，请按现象修正：

现象：
1. 我当前看到的效果：
2. 我期望的效果：
3. 涉及截图/示意图：

要求：
1. 先分析原因。
2. 给我几个可行修正方案，或直接按我们已确认规则修正。
3. 如果会影响文档或示意图，也同步更新。
```

## 9. 让 AI 做开发检查
适合：
- 需求写完了
- 文档改很多次
- 想从开发视角查冲突

模板：
```txt
开发检查

请你从开发人员视角重新检查当前需求文档 / 开发方案 / 代码实现。

重点检查：
1. 配置结构是否冲突
2. 规则描述是否有歧义
3. 状态机和时序是否自洽
4. 文档和代码是否口径一致
5. 是否存在程序无法直接实现的缺口

输出时请给我：
1. 问题清单
2. 严重级别
3. 具体位置
4. 修改建议
```

## 10. 让 AI 沉淀项目全局规则
适合：
- 某条经验和当前游戏业务无关
- 下个项目也适用

模板：
```txt
这条我认为可以作为项目全局规则。

请你先分析：
1. 它是否和当前游戏业务强相关
2. 是否适合抽成跨项目可复用规则
3. 如果适合，请整理成候选规则给我确认

我确认后，直接写入 prompt.txt。
```

## 11. 让 AI 整理显示对象清单
适合：
- 准备开始 UI 开发
- 需要先手动创建对象

模板：
```txt
接下来准备做 UI 了。

请先不要直接写依赖显示对象的代码，先给我一份需要手动创建的对象清单。

要求：
1. 列出每个 Panel / Prefab 的路径和名称
2. 说明建议字段名和用途
3. 说明哪些节点建议挂 Layout
4. 如果需要示意图，顺手补 SVG
```

## 12. 让 AI 先解释再实现 TODO-AI
适合：
- 代码里已经标了 `TODO-AI`

模板：
```txt
请先处理这个 TODO-AI。

要求：
1. 先根据当前代码和业务规则解释它应该怎么实现。
2. 把实现细节整理给我确认。
3. 我确认以后你再开始改代码。
4. 完成后把 TODO-AI 改成 AI-DONE。
```

## 13. 让 AI 同步文档
适合：
- 刚确认了一批规则
- UI 草图也要同步

模板：
```txt
这轮确认内容请同步到文档。

要求：
1. 更新需求文档 / 开发方案文档
2. 如果涉及界面，也同步更新 SVG 草图
3. 保证文档和当前代码口径一致
```

## 14. 一句话建议
- 如果你不知道该怎么提，最稳的方式就是：
  - 先给主玩法界面示意图
  - 再给一段主玩法描述
  - 有 PDF / Word 或补充规则就继续补
  - 最后说明“先整理需求”还是“先进入开发”
